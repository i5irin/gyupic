## 2026-01-04（WebP Capture Time support）
- **進捗**: WASM metadata-core で WebP の RIFF/VP8X/EXIF チャンクを再構築し、Capture Time を EXIF chunk に書き戻せるようにした。既存の VP8X があればフラグのみ更新、無ければ VP8/VP8L からキャンバスサイズを推定して VP8X + EXIF を挿入する構成。derive 側も WebP EXIF chunk を自前で抽出して `Reader::read_raw` へ渡すフォールバックを追加。`npm run wasm:build` 成功。
- **仕掛**: 実際の WebP 出力（OffscreenCanvas 由来）を使った end-to-end 検証と `docs/tests/preset-scenarios.ja.md` への証跡記録が未着手。VP8X が無い WebP で α や ICC など別フラグが必要なケースは未検証。
- **懸念**: AVIF/GIF など他形式は依然 Warning のみ。WebP でキャンバスサイズを推定できなかった場合は Warning に落ちるため、edge case の再現性チェックが必要。
- **次アクション**: (1) WebP 出力Preset（Photos→Folders等）で Capture Time バッジ／Warning を確認し、set-30-light 証跡を記録。(2) α/ICC/XMP入りの WebP で VP8X フラグを壊していないか要確認。(3) AVIF 向けCapture Time書き込み計画を立案。

## 2026-01-04（PNG Capture Time derive fallback）
- **進捗**: metadata-core の `derive_capture_time_from_exif` で PNG 判定時に eXIf チャンクを自前スキャンし、`Reader::read_raw` で直接解析するフローを実装。これにより PNG 再入力時でも撮影日時を取得できるようにし、`npm run wasm:build` でビルド成功を確認した。
- **進捗（追加）**: `eXIf` チャンクから `Exif\0\0` プレフィックスを除去してから `read_raw` に渡すよう改善し、TIFFヘッダのみを解析対象にした。これで PNG 再投入時に `META_MISSING_INPUT` Warning が出続ける根本原因を修正。
- **進捗（検証）**: PNG→PNG→再投入（JPEG変換含む）を手元で実施し、Warningが発生しないことを確認。`docs/design.ja.md` へガイドラインも追記済み。
- **仕掛**: PNG 再投入で Warning が消えるかの実ファイル検証は未着手。WebP/AVIFのCapture Time書き込み・再読込は依然未対応。
- **懸念**: 今回はCapture Timeのみ対応。GPS/XMP/ICCベストエフォートの再入力検証も必要で、`docs/tests/preset-scenarios.ja.md` への証跡が未記録。
- **次アクション**: (1) PNG→PNG→JPEG の再入力テストを set-30-light で実施しログ化。(2) WebP/AVIF向け書き込み＆deriveロジックをRust側へ拡張。(3) Warning表示が仕様通りか UI で確認し、必要なら文言チューニング。

## 2026-01-04（PNG Capture Time injection）
- **進捗**: Rust/WASM の `apply_metadata` で PNG eXIf チャンクへ Capture Time を再生成して書き込む処理を実装し、既存の eXIf を除去して IHDR 直後に差し込むよう統一。TS フォールバック（metadataPolicy.ts）でも同じロジックを実装し、WASM が読み込めない環境でも PNG 出力の撮影日時が維持されるようになった。`npm run wasm:build` / `npm run build` でセット一式を確認済み。
- **仕掛**: WebP/AVIF/GIF など PNG 以外の非JPEG形式では依然として Capture Time 書き込みができず、WASM 側も `META_UNSUPPORTED_OUTPUT` を返している。TS フォールバックは WebP/AVIF で「WASM が必要」Warningを表示するだけの暫定対処。
- **懸念**: PNG 以外では Warning のみになるため、`Photos→Photos` 以外のPreset（WebP等）で Phase3 の要件を満たせない。WebP の VP8X/EXIF chunk 追加や AVIF Exif item 生成は未着手なため、Phase3 クローズ条件に影響する。さらに、Capture Time を保持した PNG を一度ぎゅっぴくで PNG に変換→ダウンロード→再度 JPEG へ変換しようとすると `Capture time metadata was not found in the source file.` Warning が発生しており、再入力時の eXIf 読み込みに問題がある可能性が高い。
- **次アクション**: (1) Rust 側で WebP/AVIF 向け Capture Time 書き込みロジックを追加し、TS フォールバックも最小限サポートする。(2) PNG 実装の単体テスト/回帰テスト（PNG→PNG/Photos→Photos）を `docs/tests/preset-scenarios.ja.md` に記録。(3) Warning UI で「WASM依存機能」を明示し、WebP/AVIFが未対応であることを周知する。

## 2026-01-04（Capture Time mode separation）
- **進捗**: ProcessingPipeline から WASM へ `timestampWriteMode` を伝搬し、Rust 側の derive/apply が `copy-exif` / `from-file-modified` を仕様通りに振り分けるよう改修。mtime は秒精度へ切り捨てて書き戻し、取得できない場合は `META_MTIME_UNAVAILABLE` を返す。`npm run wasm:build` と `npm run build` で型チェック/バンドルを確認済み。
- **仕掛**: PNG/eXIf など JPEG 以外への Capture Time 書き込みは未対応。TS fallback (`metadataPolicy.ts`) が旧ロジックのまま残っており、完全にRustへ置き換わっていない。
- **懸念**: derive/apply を Rust へ寄せる過程で Warning の重複や英語文言のみのままになっている。TS 側フォールバック時は以前の挙動（Exif無=mtime fallback）が残るため、WASM失敗時は旧仕様へ戻る点に注意。
- **次アクション**: (1) PNG/WebP など非JPEG書き込みの対応案を整理。(2) GPS/XMP/ファイル名プラン I/F を Rust 実装へ拡張。(3) TS fallback を縮退用途だけに絞り、Warning 表示をWASM由来コードへ統一。
